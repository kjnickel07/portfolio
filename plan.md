# Personal Portfolio Website Prompt

You are an award-winning frontend engineer, interaction designer, and creative developer.

Your task is to build my personal portfolio website.

---

# Core Rule

The attached `design.md` is the **single source of truth** for the visual design.

Do **not** recreate the reference website.

Instead:

- Preserve the typography.
- Preserve the whitespace.
- Preserve the editorial/document aesthetic.
- Preserve the minimalist philosophy.
- Preserve the overall design language.

But reinterpret it into a portfolio that feels uniquely mine.

I want visitors to immediately recognize that the design is inspired by the reference while still feeling completely original.

---

# Vision

The website should make visitors think:

> "Holy shit... this is one of the nicest portfolio websites I've ever used."

Not because it has flashy animations.

Because everything feels incredibly intentional.

The entire experience should feel:

- Premium
- Calm
- Editorial
- Minimal
- Elegant
- Interactive
- Highly polished

Think somewhere between:

- Apple
- Linear
- Framer Award Winners
- Stripe
- Vercel

The site should feel like a beautifully printed editorial that slowly comes alive as you scroll.

---

# Design Philosophy

Treat the portfolio as a story instead of a website.

Every project should be experienced rather than simply viewed.

Scrolling is how the user progresses through that story.

The portfolio should be roughly:

- 80% typography
- 20% interaction

Animations should enhance the narrative, never distract from it.

---

# Tech Stack

Use:

- Next.js
- React
- TypeScript
- Tailwind CSS
- Framer Motion
- Lenis for smooth scrolling
- GSAP only if absolutely necessary

Code should be production quality.

Organize everything into reusable components.

Use clean architecture.

---

# Scrolling

Scrolling should be the defining feature of this portfolio.

I want buttery smooth scrolling.

Implement:

- Lenis
- Scroll-linked animations
- Sticky storytelling
- Motion values
- Transform animations
- Scale
- Rotation
- Blur
- Opacity
- Clip paths
- Masks
- Layered parallax
- Horizontal motion where appropriate

Everything should feel physically believable.

No snapping.

No jarring transitions.

No gimmicks.

---

# Motion Principles

Every animation should follow these rules:

- Spring based whenever possible.
- Overlapping motion.
- Follow-through.
- Anticipation.
- Momentum.
- Smooth easing.
- Subtle overshoot.
- Staggered reveals.

Animations should continue naturally even after scrolling stops.

Everything should feel expensive.

---

# Typography

Typography should remain the hero.

Do not simply fade text in.

Instead use combinations of:

- Line reveals
- Word stagger
- Mask reveals
- Blur to sharp
- Vertical motion
- Opacity
- Slight scale

Very subtle.

Very refined.

---

# Images

Images should feel embedded within the story.

Ideas:

- Reveal through masks.
- Overflow outside the reading column.
- Gentle parallax.
- Slight scale changes.
- Sticky image storytelling.

---

# Navigation

Minimal.

Elegant.

Should disappear when reading.

Reappear naturally.

Include:

- Smooth scrolling navigation
- Active section indicator
- Minimal interactions

# Project — serviceUNSW

This should become the centerpiece of the portfolio.

## Story

The project begins with an iPhone displaying the Login screen.

As the user scrolls:

- the phone slowly lifts off the page
- rotates slightly in 3D
- subtle lighting changes
- the UI animates
- login elements move naturally
- the interface morphs into the Home screen

This should NOT be a hard cut.

The transition should feel like the app is coming to life.

Ideas:

- individual UI components animate
- cards move independently
- icons appear
- realistic spring animations
- glass reflections
- layered parallax
- scroll-driven rotation

I want visitors to stop scrolling just to watch it.

# Performance

Maintain 60fps.

Use GPU transforms whenever possible.

Lazy load heavy assets.

Avoid layout thrashing.

Use Motion Values efficiently.

Keep JavaScript lightweight.

---

# Accessibility

Support:

- keyboard navigation
- reduced motion
- semantic HTML
- ARIA labels
- proper heading hierarchy

Animations should gracefully degrade.

---

# Code Quality

Write production-quality code.

Requirements:

- reusable components
- clean folder structure
- documented animation logic
- no duplicated code
- scalable architecture
